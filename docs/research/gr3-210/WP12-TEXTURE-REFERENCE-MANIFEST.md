## Source-only buffer decision before implementation

Root considered orienting the colour-only output before texture processing, which would avoid consuming source and remove the explicit copy. Independent allocation review found it pixel-correct but rejected it for this epoch: the returned left raster would remain live during MTF/halo/grain scratch. In particular, `core/src/color/grain.ts`'s odd-width geometry path pads a full RGBA raster and recursively allocates four Y/C byte planes. Early orientation can therefore keep one additional full image live during that stage. Retain the manifested private-copy timing and orient both returned planes after textures. These are conservative source-derived lifetime sizes, not measured browser peaks. No implementation/probe or further allocation research followed this rejected alternative.
