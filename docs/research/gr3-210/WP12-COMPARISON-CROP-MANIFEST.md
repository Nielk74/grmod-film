- Require the exact eligible scope, Film colour mode, attached declared main, current completed full result and available existing host. - Bound the output canvas and annotation text layout. Two 512 × 512 RGBA crops use 2,097,152 bytes in total; the one annotated PNG canvas must stay below 4 MiB of RGBA. Stage scratch/GC/PNG encoder allocation is not a measured memory-peak promise. No additional persistent crop/output state or saved format.
- Encode the bounded PNG before opening the existing directory picker. Existing `host.pickDirectory`, `host.join` and `host.write` are sufficient; preserve `host.join`'s receiver because it reads `this.sep`. Generate a unique constant-derived PNG basename, independent of all user metadata. The wrapper uses the backend's default overwrite=true; this is not an atomic no-clobber guarantee and does not authorize a new host API. Independently compute the encoded PNG's SHA-256 with the existing utility and compare **both** returned size and digest before success; `host.write` itself merely parses the verified backend response. Cancellation of the picker performs no write and needs no warning.
- Before write dispatch, revalidate an opaque current-owner key after each encode/blob/hash/picker await and immediately before calling `host.write`. Mode/source/film/recipe/sky/firmware/model/main/eligibility changes or unmount invalidate that pending action. Staleness detected before dispatch writes nothing and provides concise retry feedback only while its component is current.
- Once `host.write` is dispatched, always await and verify that captured PNG/path, independently of later preview changes. The current API cannot revoke it. Its completion describes the captured snapshot/file, never newly current settings; do not return a pre-dispatch stale/cancelled/no-write outcome after the write await. I/O errors or size/digest mismatch can leave a file: report unverified output/unknown outcome without success or a claim that nothing was saved. A small component unmount may suppress its toast, but cannot change the dispatched write's ownership or verification.
- Permit at most one action at a time. Local busy/toast changes, inspecting the divider/loupe/pan and saving must start zero converter, firmware-build or detail-render jobs. Errors must release the busy state and permit a fresh action. Saved settings, paired comparison pixels, existing output/build flows and source ownership remain unchanged.
